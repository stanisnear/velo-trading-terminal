Base Sepolia chain 84532, mock USDC, active `VeloPerpsV4` at `0xE9AEcFbc5814ce3b2dB0107594d80F054e6dB52f`. The deployment transaction is in the [manifest](../contracts/deployments/base_sepolia.json). [BaseScan](https://sepolia.basescan.org/address/0xE9AEcFbc5814ce3b2dB0107594d80F054e6dB52f#code) and [Sourcify](https://repo.sourcify.dev/contracts/full_match/84532/0xE9AEcFbc5814ce3b2dB0107594d80F054e6dB52f/) verify source/compiler correspondence, not security.

Frontend commit `84f3ce8` published sign-in recovery, V4-only active-state hydration, confirmed protection rows/cancellation and glass management dialogs. This documentation/navigation update follows it; use Git history and the Pages check for the exact later release commit rather than assuming a build is live.

## Acceptance evidence

The explicit `scripts/testnet-acceptance.mjs` run used a disposable wallet, not a user's account. On 21 October it confirmed:

- Expiring wallet challenge/signature verification and test identity logout.
- Fresh authenticated BTC/SOL oracle requests and HYPE execution updates.
- Gas sponsorship and a confirmed mock-token transfer.
- HYPE position 11 opened with TP and SL in the same transaction: [entry receipt](https://sepolia.basescan.org/tx/0x15c4833e072e738f691288ddc5ac6193660905ec6daeadcb52efb1589bb3a42b).
- Trigger editing and rereading, then cancelling TP while verifying SL remained; the UI projection changed from two protection rows to one.
- Full HYPE close classified as `CLOSE`, not liquidation: [close receipt](https://sepolia.basescan.org/tx/0xafaba829fd628d849e66130cfc2136d2ef1740440016e5ed8ae78262491a14a1).
- A distant limit entry was created and cancelled. The fixture was left without that position/order.

The successful run observed approximately 3.2 seconds for open, protection editing and close, including chain confirmation; these are single-run measurements, not a latency SLA. An earlier attempt encountered an oracle 503 and a network connection timeout. It was not counted as a pass; the successful retry is not evidence that provider outages cannot recur.

## Automated and visual verification

The `84f3ce8` release passed 191 Node tests, TypeScript and the Cloudflare production build. Coverage includes transaction ambiguity, auth cancellation/late responses, protection projection and cancellation, unsupported V4 writes, activity reconciliation and social integrity. The subsequent coin-back-navigation regression tests cover the actual JSX button event boundary and malformed ticker input.

The documentation/navigation update passed **195 terminal tests and 9 landing tests**, TypeScript and both production builds. A browser check followed BNB's All Markets button to `/markets` without an error. Documentation tests check local reference links, V4 configuration/market consistency, public counts, oracle age, article agreement and obsolete claim removal.

The management dialogs were visually checked in light/dark themes and at mobile width; the save action remained visible without horizontal overflow. The canonical app served the expected release asset hashes, and a new authenticated trading tab restored the session. Those checks do not cover every wallet/provider/device or every order-trigger scenario.

## Not established by this release

- No independent smart-contract audit, real-fund test, production security certification or exhaustive adversarial review.
- No complete event-indexed historical ledger, tamper-proof ranking or genuine-user traction measurement.
- No exhaustive bridge-route, app-session lifecycle or mobile-wallet acceptance matrix.
- No independent keeper-trigger deadline guarantee; setting/editing/cancelling protection is not a guarantee of future fills during an outage.
- No automatic legacy position migration, database deletion, new contract deployment or newly awarded grant.
