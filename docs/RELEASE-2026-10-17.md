# Market discovery and interaction reliability - 17 October 2026

## Scope

- Preserve the deployed RPC, signature login, receipt recovery and keeper changes
  based on `b72437a`. No contract replacement or mainnet activation.
- Independent top-50 CoinMarketCap directory, asset information and 24h/7d/30d
  history. Provider identity is numeric, never inferred from a ticker match.
- Only BTC, ETH, SOL and DOGE offer perpetual entry. USDT, USDC, WBTC and
  JITOSOL are excluded. PYTH, BNB, XRP, HYPE and STETH still need contract
  registration before enabling orders. Legacy position IDs are unchanged.
- CoinMarketCap runs behind `/api/market-data` with a server-only secret,
  bounded requests and shared public-data caches. No visitor credentials are
  forwarded. Failure is an explicit unavailable/retry state, not generated data.
- Posts retry with a stable UUID and verify uncertain insert responses. Likes,
  reposts and comment likes use desired state, prevent repeated in-flight clicks,
  and roll back only the acting user's membership on failure.
- Follow writes are owner-only and idempotent; counters are maintained by the
  database. Feed/relationship indexes were added without removing social data.
- Market selection and profile editing use a native modal dialog, focus
  restoration and reduced-motion support. Profile drafts survive refreshes and
  remain open on failed saves. Other dialogs retain their existing implementation.
- Landing, docs, both testnet articles and repository READMEs distinguish
  information-only assets from tradable markets.

## Verification

- TypeScript and Cloudflare production build pass. Existing wallet-library
  circular-chunk and bundle-size warnings remain; this is not a performance SLA.
- 138 Node regression/component tests pass. Fixtures cover the public gateway,
  provider-ID collisions, unavailable history, 50 rendered market rows, trade
  restrictions, timestamp spacing, narrow chart labels, profile-save retries,
  dialog cancellation/focus restoration, social persistence and existing
  trading/auth/receipt recovery.
- Production smoke testing caught a Workers/Node redirect-mode difference.
  Provider fetches now use Workers-compatible manual redirects; every redirect
  is rejected before parsing, and the API key never follows another host.
  The bundled Worker was then tested in workerd through Miniflare using the
  production compatibility date: 50 listings, coin metadata and all three
  history ranges returned HTTP 200 with the real provider.
- Live local API checks returned 50 assets; Bitcoin history returned 97, 85
  and 61 real timestamped samples for 24h, 7d and 30d respectively.
- Source and generated output were scanned for the configured CoinMarketCap
  secret: no match. Local environment and test wallet files are ignored.
- `tests/follow-integrity.sql` passed against Supabase inside a rolled-back
  transaction: repeated follow/unfollow, exact counters, legacy client
  compatibility, forged-actor/self/anonymous rejection and public reads.
- Direct database inspection confirms internal follow triggers are not callable
  by anon/authenticated; `set_following` is invoker-only and authenticated-only.
  The broader Supabase advisor request failed with a connector internal error;
  no claim of a clean project-wide advisory report is made.

## Remaining limits

Browser control reports "Local browser use is disabled in Work settings" even
with the user's Browser toggle visibly enabled. Resetting the tool connection
did not resolve it. JSDOM component tests do not verify actual native focus
trapping, stacking, desktop/mobile screenshots or wallet-extension interactions.
Those remain outstanding, including visual review in both themes.

This release is not a complete security audit, redesign of every dialog, or
proof of mainnet readiness. The contract accounting defects, legacy account and
social authorization cutover, plaintext browser wallet keys, broader moderation,
and full long/short/stop/partial-close/outage matrix remain release gates.
CoinMarketCap caching is per Cloudflare location and not a global credit cap.
Monitor quotas and provider entitlements before expanding traffic.
