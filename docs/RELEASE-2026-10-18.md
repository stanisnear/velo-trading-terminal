# 18 October 2026: navigation and interaction release

This release preserves the current V3.1 Base Sepolia contract, positions, registry
indices, hosting configuration and market-data providers. It is not a new contract
deployment or certification of mainnet readiness.

## Changes

- Explicit account choice after session expiry; manual logout awaits wallet
  disconnect and local Supabase sign-out. Late sign-in results are ignored.
- Compact canonical `/p/<id>` and `/p/<id>/r/<reply>` links retain complete UUIDs.
  Existing social links remain supported. Reply previews validate their parent;
  crawler HTML is not cached as the human SPA.
- Insightful, celebrate and bullish reactions use one row per actor/post, RLS,
  optimistic updates, rollback on failure and realtime refresh.
- Social notification writes validate the actual follow, like, reply, repost or
  mention. Messages are generated server-side and duplicate events are bounded.
  The legacy cross-user activity RPC is no longer executable by public clients.
  Transfer notifications come from the receipt-verifying backend.
- Trade entry shows pending state immediately, reports invalid TP/SL inputs,
  removes the silent one-second click throttle, and parallelizes independent
  registry/gas reads. Receipt confirmation is still required for success.
- Order-detail actions now call the real close/edit/cancel handlers. Dialog focus
  survives price updates. The closed mobile drawer is inert and casts no shadow.
- Neutral dark surfaces, matching chart backgrounds, softer grid/crosshair,
  compact market-data attribution and price precision for exchange candles.
- Admin registration is restricted to approved markets, detects occupied slots
  and waits for a successful receipt. Candidate markets remain unavailable until
  registry and keeper rollout is explicitly completed.

## Verification

- TypeScript, 149 Node/component regression tests, frontend production build,
  backend bundle and landing build pass. Existing vendor chunk warnings remain.
- Live SQL reaction and notification fixtures passed and rolled back their data.
  They cover ownership, invalid events, wrong reply parents, anonymous rejection,
  deduplication and rejection of unverified financial notifications.
- Disposable Base Sepolia wallet: signed authentication, all 13 entitled feeds,
  gas sponsorship, token transfer, isolated SOL open/close, distant limit/cancel
  and logout succeeded. The first run reused a funded fixture, so it did not mint
  new faucet tokens. On-chain confirmations took approximately 5-7 seconds; that
  is separate from immediate button feedback, not a latency guarantee.
- A second, freshly generated Base Sepolia wallet also passed signed login,
  gas sponsorship, faucet mint, token transfer and logout. Faucet mint confirmed
  in 5.7 seconds and transfer in 6.1 seconds. The fixture is isolated from user
  wallets and its private key is excluded from Git.
- Browser checks covered the account chooser/provider picker, focus restoration,
  mobile drawer, light/dark charts and responsive landing showcase controls.
  Browser access was disabled during the remaining checks. A complete real-wallet
  desktop/mobile acceptance matrix has not been completed.

## Release boundaries

The enabled perpetuals remain BTC, ETH, SOL and DOGE. Top-50 reference markets
remain independent of trading eligibility. USDT, USDC, WBTC and JITOSOL are not
perpetual entry markets. No user funds or contract registry entries were changed.

The V4 candidate, legacy credential/privacy cutover, trusted performance indexer,
contract accounting/solvency review and wider wallet acceptance remain separate.
See the engineering audit and audit-plans directory. The Supabase advisor still
reports executable SECURITY DEFINER functions and disabled leaked-password
protection; reviewed notification permissions do not establish full security.
