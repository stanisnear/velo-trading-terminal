# Identity, position attachments and PnL images

The application now separates compact position attachments from PnL image cards. The social composer can attach an existing open position while preserving the written note. Trading/history sharing also offers both formats. Closing a position shows a small optional Share action in its confirmation; it does not open the full publisher automatically.

The sharing studio puts the preview first, with inline amount/percentage and light/dark controls. Velo and Clean layouts share the product typography and restrained sage/neutral palette; layout and live-post options sit under Customize. Legacy layout identifiers remain readable. A snapshot stays fixed. A live Velo post follows the V4 position and either shows confirmed realized PnL at settlement or keeps the originally captured PnL with an explicit closed-snapshot label. Saved/native-shared PNGs are always snapshots. Live images are rendered as PNGs in the feed; stored snapshot images use the public `post-images` bucket with authenticated owner-folder writes, PNG-only MIME and a 5 MB server limit. Existing position posts now use the compact attachment layout. Chain refresh runs every ten seconds while visible; older settlements may require additional history scans.

The selected profile username is verified by a returning database update during onboarding. Revision guards prevent an older session hydration from replacing a newer onboarding/profile result. Bootstrap wallet metadata is excluded from cached restores and public labels, and the account pill has a bounded, truncating layout. Profile changes also refresh identity independently of financial balance synchronization.

Earlier profile-image and mobile session fixes are retained: unique avatar/banner URLs, owner-only writes, persisted authenticated reloads, explicit logout and idle/absolute expiry. This release does not change the V4 engine or user balances.

The landing sequence now pulls back, approaches, opens, tours the five product previews and closes on both phone and desktop. The lid and deck retain matching geometry; the camera changes from the closed overhead view to the open keyboard view. Laptop and caption form one centered group, with a shorter final handoff and no oversized caption background. The changed stylesheet URL is versioned to bypass previously cached assets.

Validation: 217 application tests, type checking, the Cloudflare production build, 14 landing checks and the static landing build passed. Browser checks covered compact composer attachments, preserved notes, optional close sharing, independent card appearance, PNG export and retained drafts on publication failure. Live disposable-account Storage checks confirmed own-folder uploads/public PNG reads, cross-user rejection, MIME rejection and fixture cleanup. No user trades, balances or social posts were changed for these checks.

Position attachments now expose margin invested when amounts are enabled and offer the same percentage-only display in the social composer. Their clickable, keyboard-accessible details dialog checks current V4 state and validates opening/settlement receipts against the fixed engine, owner and position ID. Opening terms and block timestamps come from matching logs; unavailable receipts stay explicitly unavailable. Times use the viewer’s locale and time zone. Percentage-only choices also hide invested/notional/PnL amounts in the details dialog. Snapshot details distinguish the captured post from current chain reads.

A live read of the existing HYPE position #15 recovered its opening receipt and block timestamp from a bounded log window. The primary RPC limits log queries to 200 blocks; small receipt lookups stay within that range and wider settlement-history scans use the existing public backup as a read-only source. Transaction submission and the V4 contract are unchanged. Browser checks covered the two layouts, independent light appearance, return-only image export and receipt details.
